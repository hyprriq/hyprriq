## HEADLINE (post-audit)

The independent Fable audit (see `HyprrIQ_Fable_Audit_v1_2026-07-05`) found the system is **"a well-designed judgment engine wired to an unstable evidence supply, with no permanent record of what it judged."** The core problem: the pipeline re-collects live web evidence on every run, nothing is frozen, and delivered verdicts are mutable — so the same supplier can get different verdicts on different days. The verdict *math* is proven deterministic; the *evidence feeding it* is not. The fix is one architectural layer (evidence snapshot + immutable records) that the ADRs already specified. **This is pre-launch, in a test corpus — every issue was caught before a paying client.**

**Track 3 is confirmed NOT the next build.** The integrity layer is.
