> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** DRAFT — founder-review artifact. **No code until this plan is approved** (same gate as H1).
**Phase:** H2 ONLY (ADR-G007 roadmap; H1 FROZEN 2026-07-05). Nothing from H3–H7 is bundled. Structured outputs stay in H7 (they *reduce* failure frequency; H2 makes every failure loud).

**Goal:** the engine always knows when it failed and never ships a failure as a finding — an LLM/parse failure becomes `n_a` + hold-from-auto-publish (never `soft_fail`), persistence failures surface instead of finalizing incomplete cases, no case can wedge silently, and every dead-end status actually goes somewhere.

**Why mandatory (tracker, SETTLED section):** the automation model is full-automation/human-optional. There is no human backstop to notice a silent infra-error-scored-as-`do_not_rely`. Production already shipped this failure class: two Ingram Micro runs scored `soft_fail/0` from "could not parse model output" and those alone drove `do_not_rely` verdicts.

**Frozen-core guarantee:** `deriveTrackSignal`, `computeVerdict`, `weights.ts`, the 6-gate firewall, Evidence Pack contract, ADR-G003/G004, and all H1 ledger semantics — **untouched**. "Manual review" wording below means *hold from auto-publish + flag for optional intervention*, per the settled automation model.

**Ground-truth anchors (verified this session):**
- API errors throw into the `catch` in `lib/research/track1.ts:56-62` / `track2.ts:71-77`; but **unparseable model text does NOT throw** — `parseModelJson` returns `{ _raw, _parse_error: true }` (`lib/ai/providers/anthropic.ts:25-28`) which the track parsers silently collapse to empty items (`track1.prompt.ts:76-80`). Both paths currently end as `soft_fail` via `signals.ts:34`.
- The only Inngest function has no `concurrency`/`onFailure`/cron (`lib/inngest/functions/pipeline.ts:69-72`; registration `app/api/inngest/route.ts:15`).
- `request_investigation` sets `research_running` with no `inngest.send` (`app/api/admin/cases/[id]/review/route.ts:59-71`); `confirm-scope` sets `queued` which nothing consumes (`app/api/cases/[id]/confirm-scope/route.ts:49-54`); a submit-time `inngest.send` failure is logged, the client still gets `ok: true`, and the case stays `pending_intake` charged (`app/api/cases/submit/route.ts:152-166`).
- Live wedges that AT-2 will use: 1 case `research_running` since 06-28, 2 cases `pending_intake` 7–12 days.
- `cases.updated_at` exists with trigger (`initial_schema.sql:192, 212`) — the watchdog key.
- `cases.status` CHECK is `('pending_intake','intake_complete','queued','awaiting_client','research_running','awaiting_review','manual_override_required','qa_in_progress','approved','delivered','complete','cancelled')` (`initial_schema.sql:163-166`) — needs two new states (migration).
