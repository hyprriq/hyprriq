# SUB-GATE A — TRACK 4: Documentation Review

## THE TWO INFRASTRUCTURE FACTS THE DESIGN MUST HONOR (verified in code)

1. **OCR is schema-only.** `uploaded_files.ocr_extracted_text`/`ocr_status` exist but NO code populates them — every row sits at `ocr_status: 'pending'` forever. Track 4 cannot assume extracted text exists; extraction is part of this build.
2. **Documents self-destruct.** A DB trigger sets `delete_after = uploaded_at + 12 months`. If Track 4's frozen record referenced the file, determinism and replay would die at month 13. **Therefore: the frozen Evidence Pack must carry the EXTRACTED CONTENT, not a pointer** — judgment must survive the document's deletion (H1's principle applied to a new acquisition mode).

## ARCHITECTURE (a new acquisition MODE, the same spine)

- **Document-pack builder** (new, in the acquisition layer): loads the case's `uploaded_files` rows **where `virus_scan_status = 'clean'`** (OQ-A2 rules the never-scanned reality), downloads from storage, extracts text, and emits pack sources with `source_profile: "user_upload"` — `title` = file name + declared `file_type`, `snippet`/content = extracted text, `url: null`, provenance `acquisition_method: "manual"`. The pack freezes via the SAME `persistEvidencePack` (contract 1.1.0 unchanged — user_upload was always a legal profile). Extraction cost/latency recorded in acquisition metrics like any plugin.
- **Extraction v1 (OQ-A1):** PDF text-layer + plain-text extraction in-process; image-only documents (scans/photos) are declared `unreadable` v1 → their absence is reported honestly (an unknowns entry + a questions_to_ask asking for a text-bearing copy), NEVER scored negative. Model-vision extraction is a scoped fast-follow (its own cost/capability gate), exactly like Keepa.
- **`runTrack4`:** the Track 2/3 mirror — pack (replay-aware) → `TRACK4_OUTPUT_SCHEMA` extraction (the v2.1 14-field review as the prompt's method; analyst quartet native, the Track 3 precedent) → firewall → **consensus (fourth call site — the SO-3 rule: it carries vetoes)** → diversity-capped signal → three-part `documentation_finding` + advisories. H2 `llm_failed`/acquisition guards; H4 research_identity recorded; H5-native language.
- **Zero-uploads semantics (OQ-A3, the N2-class ruling):** a case with NO documents is an ABSENCE, not a failure and not a 0-score — recommendation: `n_a` + skipped-shape with truthful reason ("no documents were provided for review"), excluded from the verdict, never escalated, never `soft_fail`.
