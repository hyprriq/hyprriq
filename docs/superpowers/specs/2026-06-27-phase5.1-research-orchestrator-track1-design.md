# Phase 5.1 — Research Orchestrator + Track 1 vertical slice (design)

**Date:** 2026-06-27 · **Branch:** `staging` · **Builds on:** Phases 1–4.5 + ADR-G006 tables (applied).
**Goal:** Prove the entire live path on ONE real case — acquisition → Evidence Pack → Track 1 LLM
interpretation → code-derived signal → verdict → memory write — **synchronously**, before fanning out
to tracks 2–5 (later slices) and before Inngest (slice 5e).

## Locked invariants (do NOT touch in Phase 5)
- `deriveTrackSignal` / `computeVerdict` are **mathematically unchanged**. ADR-G003/G004 + all 53 (now
  70) tests stay green. Evidence-quality metadata **never** enters the scoring formula.
- The verdict firewall holds: code derives signals/verdict; the LLM only provides evidence.

## Architecture — the Research Orchestrator (new Layer 1 shape)
Layer 1 changes from "track calls the model with web_search" to:

```
Orchestrator (code) ── plugins ──▶ EvidencePack (persisted) ──▶ Track LLM (interprets only)
   Serper (primary discovery)                                      ── emits evidence_items
   whois.ts (domain age)                                              (weight_key + quality meta)
   native web_search_20250305 (fallback, DEFAULT OFF)
```

- **The LLM never decides what to search.** The orchestrator runs a track's fixed query set, gathers
  results through plugins, normalizes them into an **Evidence Pack**, and hands that to the track. The
  track LLM extracts/classifies `evidence_items` from the pack — it does not browse.
- **Plugins** (`lib/research/acquisition/`): `serper.ts` (primary), `whois.ts` (domain age),
  `nativeWebSearch.ts` (Anthropic `web_search_20250305`, config-gated, off by default). New providers
  (registries, maps, gov records, marketplace) drop in behind the same interface as needed.
- **Determinism/replay:** the raw Evidence Pack is **persisted per case** so a verdict is replayable
  from exactly what was found. (Live web is still time-varying; capturing the pack is what makes a case
  reconstructible — the same property `evidence_hash` memoization already relies on.)

### Plugin interface
```ts
interface AcquisitionPlugin {
  id: "serper" | "whois" | "native_web_search";
  acquire(query: AcquisitionQuery): Promise<RawSource[]>; // RawSource = { url, title, snippet, raw }
}
```

## source_profile — locked trust taxonomy (`lib/research/source_profile.ts`)
A canonical **code enum**, never a string, never LLM-assigned. The orchestrator assigns it from the
actual source (plugin + domain classification).

```
government_record · official_brand · official_company · registry · whois ·
marketplace · news · social · forum · user_upload · inference
```

Each profile carries deterministic defaults — these ARE the trust rules:

| source_profile     | authority_score | freshness_expectation_days |
|--------------------|-----------------|----------------------------|
| government_record  | high            | 1825                       |
| registry           | high            | 730                        |
| whois              | high            | 3650                       |
| official_brand     | high            | 365                        |
| official_company   | medium          | 365                        |
| news               | medium          | 365                        |
| marketplace        | medium          | 30                         |
| social             | low             | 180                        |
| forum              | low             | 180                        |
| user_upload        | low             | 90                         |
| inference          | low             | 0                          |

- `authority_score: "high" | "medium" | "low"` (ordinal; a numeric form can be added only if/when
  scoring-integration is ever approved — not now).
- A domain→profile classifier (`classifySource(url, pluginId)`) assigns the profile deterministically
  (`.gov`→government_record, `whois` plugin→whois, brand's own domain→official_brand, etc.).

## Evidence Quality Layer (capture + surface; NOT scoring)
Every `evidence_item` gains code-assigned quality metadata, captured at acquisition, **persisted**, and
**surfaced** in the audit/Engine-Trace view. It influences **reasoning quality + confidence
explanation only** (consumed by Phase 6 synthesis to narrate *why* confidence is what it is) — it does
**not** change `deriveTrackSignal` or the verdict.

`EvidenceItem` contract additions (additive):
- `source_profile: SourceProfile` — canonical (above).
- `source_type` — **derived in code from `source_profile`** (coarse 4-bucket map), no longer LLM-assigned.
- `authority_score: "high" | "medium" | "low"` — deterministic from `source_profile`.
- `freshness_days: number | null` — age of the source at acquisition.
- `acquisition_method: "serper" | "whois" | "native_web_search" | "manual" | "inference"`.
- `certainty` — unchanged; this **is** the verification-status axis (no duplicate field).

## Track 1 vertical slice (the proof)
- **Query set** (`lib/research/tracks/track1.queries.ts`): code-defined Serper queries parameterized by
  vendor — state business registration, LinkedIn company, BBB/trade association, address/contact
  consistency, red-flag/scam scan. (This query set is the coverage lever; tracks 2–5 get their own.)
- **WHOIS enrichment:** `whois.ts` fetches domain age → a `whois`-profile source in the pack
  (pre-injected, per v2.1 — the model never calls WHOIS).
- **Track 1 prompt** (rewritten from "search" to "interpret"): given the Evidence Pack, emit
  `evidence_items` tagged with the ADR-G003 `weight_key` (so the EXISTING signal engine scores them
  unchanged) + the quality metadata, plus `reasoning_notes`, `unknowns`, and a QA-only `suggested_signal`.
- **`runAnthropic`** (`lib/ai/providers/anthropic.ts`): real Messages API via `runModel`, temp 0,
  `max_tokens` 4000, structured JSON output, `web_search_20250305` **gated off** for track calls, with
  token/cost/latency capture into `RunModelResult`.
- **`writeIntelligence`** (`lib/data/intelligence.ts`): real upsert into `vendor_intelligence` +
  `brand_intelligence` keyed on `normalizeName()` — append `risk_history`/`known_brand_relationships`,
  set `overall_risk_signal` (latest code-derived signal), increment `case_count`, stamp
  `last_reviewed_at`. **Fires on case completion from case #1.**
- Tracks 2–5 stay stubs this slice; synthesis stays stub (Phase 6); execution stays **synchronous**.

## Error handling / cost safety
- Plugin failures **degrade gracefully** — a provider being down yields fewer sources + an explicit
  `unknown`, never a crashed case. The pipeline still reaches a verdict on what was found.
- Per-case **query budget** (cap Serper calls/track) + per-call timeouts. Token/cost captured per model
  call for observability.

## Testing
Pure units, no live calls (providers mocked):
- `source_profile.ts` defaults + `classifySource` mapping; `source_type` derivation.
- Orchestrator query-building + Evidence Pack normalization; graceful-degradation path.
- Track 1 evidence mapping (pack → `evidence_items` with `weight_key` + quality meta) given a fixed
  model JSON.
- `writeIntelligence` upsert shape (vendor + brand rows, append semantics) against a mocked client.
- Existing 70 tests stay green (additive contract changes only).
- **Live validation:** one real case end-to-end (real Serper + WHOIS + Anthropic), walked on staging —
  confirms evidence acquired, signal derived, verdict recomputed, memory rows written.

## Out of scope (later slices)
Tracks 2–5 (`5c`), Inngest durabilization (`5e`), folding quality metadata into scoring (not planned —
quality stays explanation-only), synthesis narrative of quality (Phase 6), `case_outcomes` + vendor×brand
relationship tables (Phase 7).
